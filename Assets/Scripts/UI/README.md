# UI

Contrôleurs qui lient les `VisualElement` (UI Toolkit) aux services applicatifs. Une page = un contrôleur. Aucune logique métier ici. Voir `docs/02-Architecture.md` §3.4 et `docs/07-Interface.md`.

`MoneyFormat`/`DateFormat` centralisent tout affichage de montant/date (jamais de `CultureInfo`, cf. leurs commentaires) ; `MoneyFormat.TryParseEurosToMinor`/`DateFormat.TryParseInput` font l'opération inverse pour les formulaires. `AppBootstrap` (MonoBehaviour) construit l'`AppContainer` au démarrage de la scène, puis un `ShellController` (barre latérale + zone de contenu, `Shell.uxml`) qui échange le contenu affiché au lieu de charger d'autres scènes (`09-Decisions_techniques.md` ADR-113). Chaque écran suit le même patron : `XViewModel` (données déjà formatées) + `XViewModelBuilder` (pur C#, construit le view model depuis les services `App` nécessaires — pas forcément tout `AppContainer` — testable sans UI Toolkit) + `XController` (lie le view model aux `VisualElement`, et pour les écrans avec mutation comme `AccountsController`/`TransactionsController`/`RecurringOperationsController`/`ForecastsController`, appelle directement le service `App` puis se ré-affiche — testable sans rendu, cf. `09-Decisions_techniques.md` ADR-112/113). `DropdownOption` (id + nom) est le type partagé par tous les menus déroulants compte/catégorie — la sélection se résout par index, jamais en comparant le texte affiché. `ForecastsController` est la seule exception au patron « services minimaux » : comme `DashboardController`, il prend tout `AppContainer` plutôt qu'une liste de services, parce que l'écran synthétise réellement plusieurs domaines à la fois (comptes, prévision, occurrences, catégories, réglages). `Dashboard`, `Comptes`, `Transactions`, `Opérations récurrentes` et `Prévisions` existent ; seul le graphique de trésorerie (§8) et les écrans Budget/Paramètres de §3 de `07-Interface.md` restent à construire. **Ne pas utiliser de membre BCL .NET Standard 2.1+ (ex. `Dictionary.GetValueOrDefault`) dans cet assembly** — `TryGetValue` seulement, cf. ADR-114.
