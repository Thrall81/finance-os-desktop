# UI

Contrôleurs qui lient les `VisualElement` (UI Toolkit) aux services applicatifs. Une page = un contrôleur. Aucune logique métier ici. Voir `docs/02-Architecture.md` §3.4 et `docs/07-Interface.md`.

`MoneyFormat`/`DateFormat` centralisent tout affichage de montant/date (jamais de `CultureInfo`, cf. leurs commentaires) ; `MoneyFormat.TryParseEurosToMinor` fait l'opération inverse pour les formulaires. `AppBootstrap` (MonoBehaviour) construit l'`AppContainer` au démarrage de la scène, puis un `ShellController` (barre latérale + zone de contenu, `Shell.uxml`) qui échange le contenu affiché au lieu de charger d'autres scènes (`09-Decisions_techniques.md` ADR-113). Chaque écran suit le même patron : `XViewModel` (données déjà formatées) + `XViewModelBuilder` (pur C#, construit le view model depuis les services `App` nécessaires — pas forcément tout `AppContainer` — testable sans UI Toolkit) + `XController` (lie le view model aux `VisualElement`, et pour les écrans avec mutation comme `AccountsController`, appelle directement le service `App` puis se ré-affiche — testable sans rendu, cf. `09-Decisions_techniques.md` ADR-112/113). `Dashboard` et `Comptes` existent ; ni le graphique de trésorerie ni les autres écrans de §3 de `07-Interface.md` ne sont construits.
